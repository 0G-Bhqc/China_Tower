# 不可信 3ds Max 场景隔离转换 SOP

适用对象：`3D资产/` 下 5 个 `.max` 文件。  
状态：执行模板；当前尚未连接获批的隔离转换主机。

## 1. 硬性原则

- 原始 `.max` 视为含主动内容的不可信文件。
- 不在开发机、设计师日常工作机或联网生产机中打开。
- 不执行场景脚本、启动脚本、脚本化自定义属性或任何场景提示的命令。
- 原件只读；所有净化、另存和导出写入独立工作盘。
- 隔离机不得访问项目凭据、浏览器会话、代码签名证书或共享网络盘。
- 任何安全断言为 `null` 或 `false` 时，不得把导出物标记为 approved。

## 2. 隔离机准备

1. 使用一次性虚拟机快照或专用离线主机。
2. 关闭网络，移除共享剪贴板、宿主目录映射和无关 USB 设备。
3. 安装与任务清单匹配的 3ds Max；只安装明确需要的 V-Ray 版本。
4. 在打开源文件前，由两人或自动记录共同确认所有脚本执行入口已禁用。
5. 将任务目录复制到隔离机；重新计算源文件 SHA-256，必须与 `source-manifest.json` 一致。

具体安全选项名称随 3ds Max 版本变化，因此不得依赖一张固定 UI 截图。执行记录必须写明版本、设置导出或屏幕证据、操作者和复核者。

## 3. 净化与检查

1. 以脚本禁用状态打开源场景，不响应任何运行/修复脚本提示。
2. 记录缺失插件、代理对象、材质、贴图、单位和坐标轴警告。
3. 移除脚本化自定义属性、未知回调和持久化脚本，不执行其内容。
4. 不进行视觉重建或手工合并；净化阶段只移除主动内容。
5. 另存为 `outputs/sanitized-scene.max`，关闭并重新打开净化副本，确认没有脚本提示和未知回调。

若无法在不执行脚本的前提下打开，任务状态改为 `rejected`，停止处理并请求供应方提供净化 FBX。

## 4. 双层 FBX 导出

### analysis-proxy.fbx

- 米制，显式记录源轴与目标轴；
- 保留名称、父子层级、实例、变换和材质槽；
- 每个对象生成可交互的代理几何；
- 不包含灯光渲染器、动画脚本、回调或可执行内容。

### full-scene.fbx

- 保留全量几何与 UV；
- 按 V2 方案的资产分片策略导出；
- 允许 V-Ray 材质降级，材质失败不得触发未知转换脚本；
- 同步输出 `object-map.json`，映射净化场景对象名、代理对象和全量对象。

## 5. conversion-report.json 最低内容

- 任务 ID、源 SHA-256、3ds Max/V-Ray 版本；
- 所有安全断言及证据路径；
- 原场景与净化场景对象/顶点/面数量差异；
- 单位、轴和导出变换；
- 缺失插件、贴图、材质降级、跳过对象和导出错误；
- 两个 FBX 和对象映射表的 SHA-256；
- 操作者、复核者、完成时间和批准结论。

## 6. 导出物放行

1. 关闭 3ds Max，扫描输出目录，不扫描/执行原场景脚本内容。
2. 将 FBX、JSON 与报告复制到中转区；不得复制净化前的临时缓存或启动脚本。
3. 在分析机上再次计算哈希并比对报告。
4. 只有报告批准、安全断言全为 `true`、输出哈希一致时，才把任务改为 `converted`。
5. Blender 首次导入仍在无网络、无自动执行插件的环境中完成。
